# X301-v2

Raw Diffie–Hellman on the Montgomery form of the Ed301 curve. Experimental:
not standardized and not intended for production use.

X301 adopts strict encoding rules modelled on
[RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html#section-5.2.3) and a
Montgomery ladder following the construction of
[RFC 7748](https://www.rfc-editor.org/rfc/rfc7748.html). Unlike X25519 and X448,
it does not accept non-canonical peer encodings: every field value has exactly
one accepted encoding. This is a design choice for unambiguous inputs, not a
claimed security advantage over X448.

## Parameters

All values come from [`math/ed301-v2.json`](../math/ed301-v2.json), SHA-256
`13f0eaf541919a1447b9d3c58e6d57eb77ffab94ebe37539c70301d6fddcfaa0`. X301 uses the
Montgomery model `B·v² = u³ + A·u² + u` and the `u` coordinate of the base
point. The twist order is `N_t = 4·q_t`:

```text
N_t    = 4074071952668972172536891376818756322102936786019054572921615708584947563249005641551956612
N_t_le = 84ca911e62530d13b204a5718d1a9ada9621c5ffffffffffffffffffffffffffffffffffff1f
```

## Secrets

A secret is exactly 38 raw bytes. Operations work on a copy, clamped as

```text
k[0]  &= 0xfc
k[37]  = (k[37] & 0x0f) | 0x10
```

giving `k = 2^300 + 4n` with `0 ≤ n < 2^298`. The clamped value must not equal
`N_t`; this comparison is over the full 38 bytes and constant-time. Because the
clamp overwrites two low bits and four high bits, 64 raw secrets map to `N_t`;
all of them are rejected. `N_t` is the only clamp-reachable multiple of `q_t`
(the next one exceeds `2^301`), and no multiple of `q` is reachable because
`4q ≥ 2^301`.

Key generation retries only this weak-secret case, with fresh random bytes.
Random-source failures and all other errors propagate. Import, export and
PKCS#8 keep the original raw secret, not its clamped copy.

## Peer public values

A peer value is exactly 38 bytes with `encoded[37] & 0xe0 == 0`, decoding to an
integer `0 ≤ u < p`. Peer bytes are never masked, reduced or otherwise
normalized; the raw integers `p`, `p + 1` and `2^301 − 1` are rejected.

## Ladder and result

Run exactly 301 iterations, from bit 300 down to bit 0, with the doubling
formula

```text
z₂ = E · (AA + A24_minus · E),   A24_minus = (A − 2)/4 mod p
```

Do not substitute `(A + 2)/4` in this formula. Curve and twist inputs are
processed identically, without point classification. The ladder must be
constant-time with respect to the secret.

A result at infinity (`Z = 0`) and an all-zero 38-byte output are errors; no
partial or substitute output is returned. The canonical small-order values
`u ∈ {0, 1, p − 1}` decode but always fail this check. As in
[TLS 1.3, section 7.4.2](https://www.rfc-editor.org/rfc/rfc8446.html#section-7.4.2),
the check is mandatory, here also outside TLS. The output is canonical, with
bits 301–303 zero.

The 38-byte result is raw DH material. Applications must apply a reviewed KDF
and authenticate the exchange.

## Error precedence

For the two-input operation, errors are reported in this order, and no ladder
runs after an input error:

1. invalid secret type or length, then the excluded clamped secret;
2. invalid peer type or length, then a non-canonical peer encoding;
3. a result at infinity or an all-zero output.

Exception classes may differ between languages; the failing input and stage
must agree. [`vectors/x301-error-precedence.json`](../vectors/x301-error-precedence.json)
tests this order.

## Test vectors and reference

[`vectors/x301-v2.json`](../vectors/x301-v2.json) contains 7 keys, both
directions of 4 DH pairs, 24 curve and twist evaluations, 33 malformed and
all-zero cases, all 64 excluded raw secrets and an iteration chain in the style
of RFC 7748 (`k₀ = u₀ = base point u`, then `(kᵢ, uᵢ) = (X301(kᵢ₋₁, uᵢ₋₁), kᵢ₋₁)`)
with checkpoints at 1, 10, 100 and 1000. The Python reference
[`reference/x301.py`](../reference/x301.py) is variable-time and for public
test data only.
